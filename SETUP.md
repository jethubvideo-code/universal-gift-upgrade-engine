# Настройка Speed Mode с телефона

Это добавка к существующему `DEPLOYMENT.md` (GitHub-only режим не трогаем —
он продолжает работать как раньше). Эти шаги нужны ТОЛЬКО для режима
«ловля номера < 1 секунды»: постоянный процесс с прямым MTProto от твоего
аккаунта.

Статус на сегодня: это Фаза A (каркас + замеры). Горячий путь (Фаза B) и
обновлённый Mini App с WebSocket (Фаза C) ещё не сделаны — см. отчёт.

## Шаг 1. api_id / api_hash

1. Открой в браузере телефона: https://my.telegram.org
2. Войди по своему номеру (придёт код в Telegram).
3. "API development tools" → заполни любое название приложения → Create application.
4. Скопируй **api_id** (число) и **api_hash** (строка) — это секреты, никому их не присылай.

## Шаг 2. Постоянный хостинг (always-on, не засыпает)

GitHub Actions сюда не годится (не постоянный процесс). Нужен сервер, который
работает 24/7. Варианты (цены на сегодня, могут измениться):

| Вариант | Цена | Когда брать |
|---|---|---|
| **Oracle Cloud Always Free** (ARM, до 4 vCPU / 24 GB) | $0/мес навсегда | Лучший вариант по цене, но при регистрации может потребовать карту для верификации и иногда нет мощностей в нужном регионе ("Out of capacity") — попробовать первым, но заложить план B. |
| **Hetzner Cloud CX22** | ~€4.49/мес (цены Hetzner выросли 1 апреля 2026) | Надёжнее Oracle Free по доступности, регионы в Европе (Германия/Финляндия). |
| **Railway / Fly.io** (free tier очень ограничен в 2026, дальше платно) | от ~$5/мес после бесплатного лимита | Проще деплоить прямо из GitHub кнопкой в браузере, без SSH — удобно с телефона. |

Регион выбирай ПОСЛЕ шага 5 (одноразовый вход) — скрипт входа печатает DC id
твоего аккаунта; тогда и смотри, какой из вариантов выше ближе.

## Шаг 3. Деплой из GitHub

Для Railway/Fly.io — через их веб-интерфейс (телефон): "New Project" →
"Deploy from GitHub repo" → выбрать `jethubvideo-code/universal-gift-upgrade-engine`
→ Start command: `npm start`.

Для Oracle/Hetzner (голый сервер) — через веб-терминал хостинга (у обоих есть
браузерная консоль, SSH с телефона не нужен):
```
git clone https://github.com/jethubvideo-code/universal-gift-upgrade-engine.git
cd universal-gift-upgrade-engine
npm install
```

## Шаг 4. Переменные окружения

В настройках хостинга (или в `.env` файле на сервере) задать:

| Переменная | Значение |
|---|---|
| `TG_API_ID` | из шага 1 |
| `TG_API_HASH` | из шага 1 |
| `SESSION_ENCRYPTION_KEY` | сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"` и сохранить ровно это значение |
| `TRANSPORT` | `mtproto` |
| `MODE` | `dry-run` (пока не готов стрелять живыми Stars — не трогать до явного перехода на `live`) |
| `BOT_TOKEN` | тот же токен бота `@lvlonebot`, что уже используется (для уведомлений) |
| `DB_BACKEND` | `file` |
| `PORT` | `8080` (или что требует хостинг) |

## Шаг 5. Одноразовый вход

В веб-терминале хостинга, из папки проекта:
```
npm run login
```
Скрипт спросит номер телефона → код из Telegram → пароль 2FA (если есть).
Всё это вводится ТОЛЬКО здесь, в этой консоли — никогда в чат бота, никому
не присылать, включая меня. После входа скрипт печатает твой DC id — это и
есть ответ на вопрос «какой регион хостинга ближе» из шага 2.

## Шаг 6. Проверка /healthz

Открой в браузере: `https://<твой-хост>/healthz` — должен ответить JSON с
`"ok": true`, `"mode": "dry-run"`, `"transport": "mtproto"`, `"dc_id": <число>`.

## Шаг 7. Замеры (обязательный шаг Фазы A)

```
npm run dryrun
```
Это реально читает Telegram (без списаний) и печатает честные числа:
латентность пробы окна, DC id, проверку последовательности номеров,
попытку прочитать твои подарки на апгрейд. Пришли этот вывод целиком —
по нему я продолжу Фазу B (горячий путь).

## Режимы

`MODE=dry-run` (сейчас) → `MODE=live` — переключение на `live` делает
только владелец и ТОЛЬКО после того, как в Mini App появится экран
подтверждения (Фаза C, ещё не готов). Пока `MODE` можно менять только через
переменную окружения на сервере — в коде нигде не включается автоматически.
